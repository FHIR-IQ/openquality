# MCP service: design

Date: 2026-10-12
Status: Implemented 2026-10-12 (`packages/mcp`, `site/api/mcp.ts`). npm publish and MCP Registry listing pending

## Goal

Let an agent harness or IDE (Claude Code, Cursor, VS Code, CQL Studio, the MCP
Inspector) pull a measure's code and the context around it, meaning provenance,
license, value set references, known issues and the CRMI Bundle, through one
standard MCP server. The server should be lean enough that HL7 groups and
measure developers can adopt it with a URL or one `npx` command.

The corpus grows separately (content expansion is a separate sub-project). Every
package the importer adds appears in this service with no change to it.

## Non-goals

- Write tools. Contributing stays on GitHub: pull requests and the issue forms.
- Auth. All content is public.
- CQL execution, translation, or terminology expansion.
- Search over value set contents. Value sets are referenced, never embedded.
- Committed build output. Nothing new is generated into the repository.

## Assumptions tested on 2026-10-12

| Assumption | Result |
|---|---|
| CRMI Bundles can be built from the catalogue's artifact list, without a directory walk | **Holds.** For all 54 packages, `buildPackageBundle` over `index.json` `artifacts` is byte-identical to `oq fhir-bundle` output. |
| Precomputing bundles is cheap | **Rejected.** 54 bundles total 13 MB (2.4 MB gzipped), largest 441 KB. Committing them grows the repository on every import. Bundles are built on request instead. |
| The SDK supports stateless HTTP on web-standard `Request`/`Response` | **Holds.** `@modelcontextprotocol/sdk@1.31.0` `WebStandardStreamableHTTPServerTransport` with `sessionIdGenerator: undefined, enableJsonResponse: true` served initialize and `tools/call`, and returned zod violations as `isError` results. |
| The SDK's zod range fits the workspace | **Holds.** SDK wants `^3.25 \|\| ^4`; the workspace resolves `zod@3.25.76`. `packages/core` declares `^3.23.0`, so raise it to `^3.25.0`. |
| The transport rejects GET in stateless mode | **Fails.** A GET opens an SSE stream that never closes. The handler must return 405 itself (see Hosted endpoint). |
| The Vercel function can import code outside `site/` | **Holds, verified on a preview deploy.** Project root is `site`, `sourceFilesOutsideRootDirectory: true`, Node 24. With `installCommand` running pnpm from the workspace root, the function bundler resolved `../packages/mcp/src/*.ts` and traced the pnpm dependencies. The fallback below was not needed. Vercel type-checks those files without strict mode. |
| `index.json` is a reliable source | **Holds.** Generated by `pnpm build-library`, and the `drift` CI job fails if the committed copy differs. Served with `Access-Control-Allow-Origin: *`. |
| npm name is free | **Holds.** `@openquality/mcp` and the `@openquality` scope are unclaimed. This machine is not logged in to npm, so publishing needs the user. |

## Architecture

```text
packages/mcp/
  src/source.ts     CorpusSource: readText(repoPath) → string
                    HttpSource(base, ref)   raw GitHub at a pinned ref, with an in-memory cache
                    FsSource(root)          a local clone
  src/catalogue.ts  loads index.json once per source; owns the path allowlist
  src/tools.ts      the five handlers, pure over a CorpusSource
  src/server.ts     createServer(source): McpServer with the tools registered
  src/stdio.ts      bin entry: npx @openquality/mcp [--ref <sha>] [--root <dir>]
  test/             vitest, collected by the existing config
site/api/mcp.ts     Vercel function, web-standard handler, stateless
site/package.json   declares the function's runtime dependencies
site/vercel.json    rewrite /mcp → /api/mcp, CORS headers for /mcp
```

Dependency direction stays one way: `mcp` → `core`. `mcp` imports
`buildPackageBundle` and `parseManifest` from `core`'s `fhir.ts` and
`manifest.ts` modules directly, not through `index.ts`. That keeps `tar`
(`pack.ts`) out of the server.

### Where data comes from

- **Hosted:** `HttpSource` over `raw.githubusercontent.com/FHIR-IQ/openquality/<VERCEL_GIT_COMMIT_SHA>/`.
  A commit's files never change, so the cache never expires within an instance.
  Fluid Compute reuses instances, so repeated calls skip the fetch. The
  deployment serves the corpus as of its own commit, and every answer names that
  commit.
- **stdio, default:** `HttpSource` at `main`. `--ref <sha>` pins it.
- **stdio, `--root <dir>`:** `FsSource` over a local clone. Works offline, and is
  what the tests use.

## Tools

All tools set `annotations: { readOnlyHint: true, openWorldHint: false }`. Inputs
are zod schemas with length caps. Handlers return `isError` results. They never
throw, following the convention `core` uses for validation.

| Tool | Input | Output |
|---|---|---|
| `search_measures` | `query` (≤200 chars), optional `collection`, `dataModel`, `limit` (≤50, default 20) | Packages whose id, title, steward or identifiers contain every query token, case-insensitive. Each result: id, version, title, steward, identifiers, license, level, relationship, knowledge count |
| `get_measure` | `id` | Catalogue entry, plus from the manifest: provenance block (upstream repo, commit, `relationship`, `modifications`), value set references, and the linked knowledge entries' summaries |
| `get_artifact` | `path` | Raw file text. `path` must appear in some package's `artifacts`, or be a knowledge `source`. Anything else is an error that names the tool and the path |
| `get_bundle` | `id` | The CRMI artifact Bundle, built on request from the package's artifacts with `buildPackageBundle` |
| `known_issues` | optional `measure`, `type`, `status`, `limit` | Knowledge entries with their full Markdown body, read from each entry's `source` |

Every result ends with the same footer block:

```text
served-from: <ref>
license: <package license, where one package is involved>
policy: Value sets are referenced by OID or canonical URL, never embedded.
        CPT display text is removed; codes and code systems are kept.
        Repackaged copy, not an authoritative publication. See TERMINOLOGY.md.
```

The footer is the reason to use this server and not a raw GitHub fetch. The
provenance travels with the code into the agent's context.

## Hosted endpoint

- `site/api/mcp.ts` builds one `McpServer` and one stateless transport per
  request, and returns `transport.handleRequest(request)`. POST only. The
  handler itself returns 405 with `Allow: POST` for GET and DELETE before the
  transport sees them. Tested 2026-10-12: in stateless mode the transport answers
  a GET by opening an SSE stream that never closes, which on Vercel would hold
  the function open until its timeout.
- `site/vercel.json`: rewrite `/mcp` → `/api/mcp`. Headers for `/mcp`:
  `Access-Control-Allow-Origin: *`, allow `content-type, accept,
  mcp-protocol-version`, and handle OPTIONS. The site CSP does not apply to an
  API response.
- Rate limiting: none at launch. Add a Vercel firewall rule only if abuse
  appears.

**Fallback** if the preview deploy cannot resolve imports from `packages/`: add
a `vercel-build` script to `site/package.json` that bundles `site/api/mcp.ts`
with esbuild into `site/api/mcp.js` at deploy time (not committed). That is the
same esbuild step the npm package uses.

## npm package

`@openquality/mcp` ships a single esbuild bundle (`dist/stdio.js`, with `core`'s
two modules inlined) because `core` exports TypeScript source and is not
published. The package has three runtime dependencies: `@modelcontextprotocol/sdk`,
`zod` and `yaml`. Node ≥22, matching the repository. `package.json` carries
`mcpName` for the MCP Registry.

## Testing

In `packages/mcp/test/`:

1. **Handlers over `FsSource`** against the real repository:
   - search: a hit by CMS id, a hit by title token, a miss, the `limit` cap
   - `get_measure` on a `derived` package lists its CPT modifications
   - `get_artifact` rejects a path outside the allowlist and a `..` path
   - `get_bundle` for every package equals `buildPackageBundle` over the same
     files (the parity check above, kept as a test)
   - `known_issues` filters by measure and returns the body, not only the summary
   - every result carries the footer
2. **Protocol:** the SDK's in-memory client against `createServer`. List tools,
   call each one.
3. **HTTP handler:** call the `site/api/mcp.ts` handler with a constructed
   `Request`: initialize, `tools/list`, one `tools/call`, and a GET returning 405.
4. **stdio:** spawn the built binary with `--root .` and list tools.
5. **Manual, before production:** MCP Inspector against the preview URL.

`HttpSource` is tested with a stubbed `fetch`. The suite makes no network calls.

## Claims discipline

The setup page and README say only what the tests prove. Read-only, five tools,
served from a named commit. They do not say "standard-conformant" beyond "speaks
MCP via the official SDK". They do not imply HL7 endorsement, and they do not
imply the CQL translates, since Level 2 is still unreachable.
